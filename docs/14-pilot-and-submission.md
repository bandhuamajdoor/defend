# Pilot, measurements and hackathon submission
## Five-classmate pilot
Recruit people who have permission to share a small project. Ask for consent to use anonymised aggregate results; separate consent for screenshots/video. Do not upload classmates' code or contact them automatically.
Script: choose sample or own project, confirm summary, complete a short interview, inspect two findings, try a retest, export/delete. Observe without coaching UI use unless they become blocked. Record assistance honestly.

Questions after trial: What felt like a real interview? Which follow-up was useful or irrelevant? Was any criticism wrong? What would you practise next? Would you use it before a viva?
A technical peer reviews every contradiction plus a sample of supported/unresolved findings. Keep notes outside the public repository; only synthetic fixtures and anonymised aggregates go into source control.

Before/after task: student explains one concept, uses Defend, then answers a new related question reviewed with a fixed rubric. Report sample size and assisted/unassisted status. Do not infer learning solely from model scores or invent time saved.
Retain aggregate results and a few permitted quotes. Delete raw participant data per the agreed policy.

## Two-minute demo outline
0:00–0:15: show the real problem and who experiences it.
0:15–0:30: select project, confirm actual project summary.
0:30–1:10: answer with Wispr; interviewer follows a concrete claim into code and asks a relevant failure scenario.
1:10–1:35: show debrief with exact answer/source evidence and uncertainty handling.
1:35–1:50: show a new retest question and one real pilot result.
1:50–2:00: public project link and brief explanation of building with Wispr.
Use real model output; edits for time are acceptable if labelled where necessary. Preload sample, test latency and browser audio; never present seeded output as live inference.

## Submission checklist
- Working public URL, no payment or organiser access request.
- Isolated sample and clear instructions; real-provider budget reserved for judging.
- Video <=2 minutes; permitted content only.
- Wispr Insights usage-card screenshot.
- Short description: problem, student audience, actual result, how Wispr supported build and workflow.
- Weekly check-in/progress evidence and social links if participating.
- Final browser test from a fresh profile.
- Save submission receipt/time and final artifact links.
